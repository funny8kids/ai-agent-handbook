# 医疗、金融、法律 Agent

> **一句话**：行业关键业务（医疗/金融/法律）是 Agent 的「高价值高门槛」区：专业准确率、合规审计、责任界定三座大山——先做「辅助人类」再谈「替代决策」。
> **难度**：高级
> **标签**：`#application` `#safety`

## 先看结论

- 共同模式：**Agent 出草稿、专业人士拍板**（医生确认诊断建议、律师确认合同条款、分析师确认投研结论）
- 准确率要求量级不同：闲聊 90% 可接受，医疗建议 99% 仍可能出人命——评估体系完全不同
- 合规三件套：审计日志（全程可回放）、可解释（结论带依据）、数据主权（PII/PHI 不出域）
- 自托管开源模型（DeepSeek/Qwen/Llama）在这三个行业渗透最快，动因就是数据主权

## 三行业对照

| 维度 | 医疗 | 金融 | 法律 |
|---|---|---|---|
| 高价值场景 | 病历摘要、影像辅助、随访 | 投研报告、风控初筛、合规审查 | 合同审查、法条检索、文书起草 |
| 错误代价 | 极高（人身） | 高（资金/监管） | 高（权益/时效） |
| 关键数据 | PHI 病历 | 交易与身份数据 | 案件保密信息 |
| 合规框架 | HIPAA/个保法 | 各国金融监管（MODEL 风险等） | 执业规范、保密义务 |
| Agent 角色 | 辅助决策（不诊断） | 辅助分析（不投资建议） | 辅助起草（不提供法律意见） |

## 源码案例

- **全链路本地化架构**（[earendil-works/pi](https://github.com/earendil-works/pi)）：pi-ai 统一接口 + vLLM pods 内网部署 + 本地 embedding——「数据不出域」的完整开源参考栈，行业敏感场景的基础设施模板
- **审计与事件流**（[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)）：append-only 会话日志天然满足「每个结论可追溯到当时输入」的审计要求；Trajectory 视图 = 合规检查工作台
- **医疗 RAG 的引用纪律**（→ [RAG 基础](../06-memory-rag/rag-basics.md)、[幻觉问题](../10-evaluation-safety/hallucination.md)）：临床知识问答必须「逐句引用指南原文 + 版本号」，拒答机制对「指南未覆盖」的问题显式声明
- **金融的结构化输出纪律**（→ [结构化输出](../04-prompt-reasoning/structured-output.md)）：风险评级等关键字段用 schema 约束 + 独立规则引擎复核，模型输出进入决策链前过双重校验

## 落地要点

- 人审节点前置设计：什么级别必须专家确认、确认界面展示哪些依据
- 领域评估集：请行业专家标注黄金集（如 100 例合同审查），LLM judge 只做初筛
- 版本化一切：模型版本、prompt 版本、知识库版本进入审计链——出问题时能复原「当时的 Agent」

## 核心机制：行业差异来自「可接受错误率」

同一套 Agent 技术在不同行业落地方式差别巨大，根源不在技术，而在**错误代价**：

$$
\text{可接受错误率}\;\propto\;\frac{1}{\text{单次错误的后果严重度}}
$$

- 闲聊/内容生成：90% 可用度即可上线，错了也无所谓
- 客服/内部工具：错误可回滚（改单、重发），容忍度中等
- 医疗/金融/工业控制：错误不可逆且后果严重，**99% 仍可能不可接受**

这条不等式直接决定四个设计变量：

| 变量 | 低风险行业 | 高风险行业 |
|---|---|---|
| 自主等级 | L2–L3 可自动 | 关键步骤必须人审 |
| 评估门槛 | 抽样评估 | 全量回归 + 专项红队 |
| 可解释性 | 可选 | 必需（审计要求） |
| 回滚能力 | 事后修复 | 事前拦截 + 幂等保证 |

### 合规与审计是硬约束

高风险行业还要额外满足：**每个结论可追溯到当时的输入与依据**、操作留痕且不可篡改、数据不出域。这些需求对应到技术上就是事件溯源（可回放）、append-only 审计日志、私有化部署——它们不是「加分项」，而是准入门槛。

因此行业 Agent 的正确做法不是「把通用 Agent 搬过来」，而是**先确定可接受错误率与人审边界，再倒推技术选型**。

一个可操作的推导顺序：① 列出该行业「错了会怎样」的动作清单；② 为每条标注可逆性与后果严重度；③ 据此决定自主等级与审批点；④ 最后才选模型与框架。顺序反了，就会做出「技术上先进、合规上不可用」的系统。这套推导也让跨行业复用成为可能：复用的是流程与工具，重新推导的是自主边界。

## 常见误区

- ❌ 拿通用榜选型：医疗问答榜高分 ≠ 穿戴「你的医院知识库」后可靠，领域内测集说了算
- ❌ 幻觉容忍度错配：生成文案的小幻觉无所谓，药名剂量的小幻觉是事故
- ❌ 责任模糊化：上线前明确「AI 建议的法律地位」并让用户知情，否则出事时全盘皆输
