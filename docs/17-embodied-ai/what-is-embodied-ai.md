# 什么是具身智能

> **一句话**：智能不只是「预测下一个 token」，还包括「在物理世界里把事办成」——具身智能研究有感官和执行器的智能体如何从与环境的交互中学习，核心难点是感知与动作之间的闭环，以及不可逆的代价。
> **难度**： 入门
> **标签**：`#embodied-ai` `#基础`

## 先看结论

- **定义三要素**：身体（传感器 + 执行器）、环境（物理定律、摩擦、遮挡）、闭环（动作改变观测，观测决定下一动作）。三者缺一，都只是「带摄像头的问答模型」。
- **和 LLM Agent 一样是循环，不一样的是失败成本**：数字 Agent 写错代码可以 git checkout，机器人抓歪了就是一次人工复位 + 一块可能的碎玻璃。这决定了具身领域格外重视「可验证、可回滚、可复位」的评估设计。
- **莫拉维克悖论仍然成立**：让模型写诗很容易，让机械臂在杂乱桌面上把一块软毛巾折叠起来极难。高级推理的计算量比「感知—动作」小得多。
- **三代范式**：模型驱动（建模 + 优化控制）→ 学习驱动（RL/模仿学习单任务）→ 基础模型驱动（VLA：互联网规模的视觉语言先验 + 机器人数据微调）。

## 为什么纯语言模型做不了机器人？

三个硬约束：

1. **动作是连续的、高频的、有动力学的**：`{"tool":"move", "x":0.3}` 不是有效指令；末端位姿、关节角度、力矩各有单位与限幅，还要满足平滑性与奇形怪状的约束（奇异点、自碰撞）。
2. **状态不可完全观测**：物体会被挡住、摩擦力不知、负载未知。策略必须对部分可观测与建模误差鲁棒。
3. **数据不在网上**：互联网有万亿 token 的文本，但没有「从机器人本体视角、带力反馈的接触操作」数据。所以「先预训练再迁移」是绕不过去的路径，而预训练语料需要人造。

## 核心概念对照

| 概念 | 机器人里的对应 | LLM Agent 里的对应 |
|---|---|---|
| 感知 | RGB-D、本体感受、触觉、IMU | 工具返回、文件内容、页面快照 |
| 记忆 | 世界模型、场景图、任务状态 | 上下文、向量库、会话存储 |
| 规划 | 任务分解、运动规划、抓取规划 | CoT、Plan-and-Execute |
| 执行 | 力矩/位置控制、伺服、轨迹跟踪 | 调用 API、执行代码 |
| 反馈 | 力觉残差、视觉误差、成功率 | 报错、测试结果、用户纠正 |
| 失败恢复 | 重新感知 + 重试或求助人 | 反思（Reflexion）、重试 |
| 训练 | 模仿学习、RL、VLA 微调 | SFT / DPO / RL |

## 生活类比

把 LLM Agent 想象成「坐在电脑前的实习生」：搞砸了就 Ctrl+Z。具身 Agent 是「端着一叠盘子走楼梯的实习生」：所有动作有惯性、视野被盘子挡住、掉一次就真碎了——所以它需要**反射弧**（不必经大脑的快反应）、**安全距离**（宁可慢），以及**反复练习过的肌肉记忆**（策略网络）。

## 技术栈分层

1. **底层**：电机伺服与驱动、力矩估计、状态估计（IMU/编码器/视觉里程计）——kHz 级
2. **控制层**：关节阻抗/力控、轨迹插值、全身控制（WBC）、碰撞检测——数百 Hz
3. **技能层**：抓取、插入、开门、递物——几十 Hz，常由学习型策略实现
4. **任务层**：任务分解、目标选择、失败恢复——1–10 Hz，VLM/LLM 或经典规划器
5. **系统层**：调度、安全监控、遥操作接管、数据回流

> 💡 **提示**：读论文时先确认它在哪一层「创新」。把「任务层用 VLM 挑目标」和「技能层用 diffusion 出动作」混着讲，是这个行业最常见的沟通灾难。

## 现实坐标（2026 视角）

- **学术与开源基线**：RT-2、Open X-Embodiment、OpenVLA、RDT、SmolVLA、LeRobot 生态，把「训一个 VLA」的门槛从实验室级拉到单机级。
- **产业前沿**：Physical Intelligence（π 系列）、Google DeepMind（Gemini Robotics 系）、NVIDIA（GR00T + Isaac/Cosmos）、Figure（Helix）、Tesla、Unitree、AgiBot（智元）、1X、Apptronik、银河通用、宇树等在推「通用机器人 + 数据采集工厂」组合。具体模型版本与指标以各家官方发布为准。
- **共同判断**：泛化能力与可靠性是当前瓶颈，量产部署集中在「窄任务 + 结构化环境」（分拣、搬运、巡检、装配辅助），家用人形仍在早期。

## 常见误区

- ❌ 「给大模型接个机械臂就是具身智能」：没有高频闭环与安全层的「自然语言 → 关节角度」demo，只能算视频素材
- ❌ 用「视频里看着很顺」判断能力：剪辑、慢放、成功样本挑选会让 20% 成功率看起来像 90%
- ❌ 把 Sim-to-Real 当成可跳过的步骤：仿真里 95% 的真机成功率可能只有 40%，差距本身就是研究对象
- ❌ 认为「人形一定最优」：双足是为人类环境兼容付出的代价（控制、能耗、安全），轮式底盘 + 双臂在很多工业场景更实际
- ❌ 忽略数据合规与隐私：家庭/工厂采集的第一视角视频涉及人脸、门牌、文件，落地前就要设计脱敏与授权

## 小练习

选一个你想让机器人完成的任务（例如「把桌上三个塑料杯放进水槽」），写下：① 需要哪些传感器；② 控制频率需求；③ 三种失败模式与检测它们的信号；④ 这个任务需要多少条演示数据（先猜，再查 [数据引擎](data-engine.md) 里的经验规律对答案）。
