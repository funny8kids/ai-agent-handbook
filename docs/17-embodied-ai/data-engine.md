# 🦾 数据引擎：机器人数据从哪来

> **一句话**：具身智能的护城河不是模型结构，而是「单位成本能买到多少条有效轨迹」——遥操作质量高但贵，免机器人采集便宜但分布不同，仿真便宜又可扩展但有 sim-to-real 差距，人类视频量大却没有动作标签。
> **难度**：⭐️⭐️ 进阶
> **标签**：`#embodied-ai` `#data`

## 📌 先看结论

- **五条来源，按「每条轨迹成本 / 可用性」取舍**：真机遥操作、手持夹爪采集（UMI 类）、仿真合成、人类视频（伪标签）、失败/纠正数据回流。成熟团队是四条混用，并显式管配比。
- **模仿学习的经验规律：数据量比模型大小更早触顶**。窄任务几十到几百条演示就能学会（ACT 的原始设置是每任务约 50 条）；跨场景泛化要上万条量级。先估「你需要多少个任务 × 每任务多少条」再决定建不建采集工厂。
- **质量在采集时决定，不在训练时补救**：一次成功演示里夹爪抖动、复位、语言指令含糊，都会成为策略的上限。要有「可入库」标准与自动质检。
- **标注/切分与真值动作是一等公民**：视频要能对齐时间戳、切子任务、生成语言描述（自动 + 抽样人审）；仿真数据必须带噪声与延迟，否则真机不可用。
- **数据飞轮的关键是「采集—标注—训练—评估—上线」的周期长度**，不是单次数据量。

## 🗺️ 来源对照

| 来源 | 单位成本 | 动作真值 | 分布真实度 | 规模上限 | 主要坑 |
|---|---|---|---|---|---|
| 真机遥操作（主从臂 / VR / 手柄） | 高（人工小时） | ✅ 直接可得 | ✅ 高 | 中（需人力工厂） | 操作员习惯偏置、疲劳导致质量漂移 |
| 手持夹爪（UMI 类）、无机器人 | 低-中 | ⚠️ 近似（运动学重定向） | 🟡 中（视角/动力学不同） | 高 | 人手 vs 夹爪可达性差异、缺力信息 |
| 仿真合成（Isaac Lab / MuJoCo / Genesis） | 极低（算力换） | ✅ 完美 | ❌ 低（需随机化） | 极高 | 接触与软体不真实、任务由人工设计 |
| 人类视频（Ego4D、Epic-Kitchens、YouTube） | 极低 | ❌ 需推断（latent action / 逆动力学） | 🟡 语义高、动力学弱 | 极大 | 无本体感受，视角与机器人完全不同 |
| 真机部署回流（失败 + 人工纠正） | 中 | ✅ | ✅ 最高 | 与部署量成正比 | 需要在线标注与隐私处理，最容易被忽略 |
| 合成视频 / 世界模型生成（DreamGen 类） | 低-中 | ⚠️ 伪标签 | 🟡 中 | 高 | 物理一致性不足，易学「幻觉动作」 |

## ⚙️ 采集与治理清单

**采集前**

1. 任务定义写成「可判定成功」的形式：目标状态 + 时限 + 允许重试次数（否则后面所有统计都没意义，见 [评估与基准](evaluation-benchmarks.md)）
2. 场景/物体多样性矩阵：桌面纹理 × 光照 × 物体类别 × 位姿范围 × 干扰物，先设计再采
3. 每条轨迹记录：多相机（含时间戳）、本体状态、动作、语音/文字指令、操作员、失败原因标签

**入库前自动质检**

```python
def accept(ep, spec):
    return all([
        ep.frames_gap_ms_max < 60,                    # 丢帧
        ep.action_jerk_p99 < spec.jerk_limit,         # 抖动
        ep.success_flag is True,                      # 只看真成功
        ep.static_ratio < 0.35,                       # 长时间静止（操作员走神）
        spec.min_steps <= ep.steps <= spec.max_steps, # 太短/太长
        ep.language not in {"", "做一下那个"},          # 指令有效性
        ep.camera_pose_variance > spec.thresh,        # 相机被撞到
    ])
# 不合格的不删，进「隔离区」，用于失败样本训练与统计
```

**训练侧的消费方式**

- **配比是第一超参**：机器人真机 : 仿真 : 人类视频/合成，常见起点约 `5 : 3 : 2`（无定式，须用你自己的评估集校准）。人类视频多用于「表征预训练」，真机数据用于「动作对齐微调」。
- **跨机型对齐**：URDF 差异导致关节数/动作维度不同 → 统一到末端 + 夹爪的动作空间，或用掩码 + 形态 token（RT-X/GR00T 系思路）。
- **数据版本 = 训练版本 = 模型版本**：三件套必须绑定；否则「哪一版数据训出这版策略」会在半年后无人可考。

## 📦 工程现场笔记

- **公开数据集是「起点」不是「答案」**：Open X-Embodiment（跨机构多机型、百万轨迹量级）、DROID（多实验室 Franka 遥操、数万条量级）、BridgeData V2、AgiBot World、RoboMIND、CALVIN/LIBERO 演示集。用它们做预训练/表征，用你自己的真机数据做适配——这是目前最常见、也最容易见效的组合。
- **ALOHA / Mobile ALOHA 的启示是「硬件为数据服务」**：低成本主从双臂 + 50 条演示就能学复杂任务，说明「采集设备便宜、任务定义清晰」比「机器人先进」更重要。
- **UMI 类手持采集的关键是「规模化后的一致性」**：夹具、相机标定、鱼眼畸变处理必须固定，否则 100 人的众包数据 = 100 种分布。
- **遥操作工厂的组织成本 > 技术成本**：排班、任务轮换、质量抽检、培训曲线。做规划时把它当人力项目，不是当算法项目。
- **飞轮的自动化程度决定迭代速度**：「部署 → 失败样本自动入库 → 夜间重训 → 仿真 + 小批真机评估 → 灰度」这条链路如果能一周跑一轮，模型进步会明显快于「季度性大数据集」。

## ⚠️ 常见误区

- ❌ 「先采 10 万条再说」：任务设计粗糙的 10 万条，不如精心设计的 5000 条。先跑通「50 条学会一个任务」，再谈规模化
- ❌ 忽略失败数据：策略只见过成功轨迹，遇到偏差就不会恢复；失败 + 人工纠正样本是恢复能力的唯一来源
- ❌ 仿真数据不加噪：完美状态 + 零延迟训出的策略，在真机上因估计误差与延迟直接失稳
- ❌ 语言标注随便写：同一动作五花八门的说法 → 语言条件失效。要有指令规范（动作 + 物体 + 目标 + 约束）
- ❌ 用「数据条数」而非「小时数 × 自由度 × 视角数」谈规模：一条双臂 50Hz 60 秒的轨迹和一帧静止的单目 5 秒轨迹不是一回事

## 🧪 小练习

给你的目标任务做一张「数据预算表」：任务数 × 每任务演示条数 × 每条秒数 = 采集小时数；再按操作员效率（如 8 条/小时）折算成人天。然后回答两个问题：① 哪些任务可以用仿真批量生成？② 哪些必须真机（因为接触/柔性/安全）？通常你会发现必须真机的任务比想象中少。
